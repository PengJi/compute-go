# 全自动多主题持仓收益诊断 Skill

## 目标

在用户仅提供持仓清单（代码/名称、金额/权重）的情况下，系统自动完成以下任务：
1. **自动聚类**：根据持仓特征，将其合理归类为若干个逻辑主题（如：底仓固收、宽基指数、科技成长、医药消费、海外资产等）。
2. **主题拆解**：计算每个归纳出的主题的仓位占比、绝对收益、对组合的收益贡献度。
3. **全局汇总**：分析主题间的底层相关性（同质化风险）、整体组合绩效，以及极端情景下的脆弱点。

适用假设：默认面向中国境内投资者的基金/股票组合；若组合以海外资产为主，压力测试情景需相应调整（如汇率方向、美股基准），并在报告中说明调整依据。

## 执行流程

1. **接收输入**：获取用户的持仓清单，确认分析区间与基准（用户未说明时直接采用下方缺省值）。
2. **自动聚类**：执行 `references/auto-clustering.md`，将零散持仓自动归纳为 3-8 个核心主题。
3. **计算贡献表**：持仓标的超过 5 个时，将持仓表写入临时 CSV，用 `python3 scripts/compute_contributions.py <csv路径>` 计算主题贡献表。必须通过解释器调用而不是裸路径执行——打包环境可能丢失可执行位。环境无法运行 Python 时，才手工逐项计算并在报告中列出算式，便于复核。
4. **单主题拆解**：对自动归纳的每个主题执行 `references/per-theme-analysis.md` 规定的计算，生成体检报告。
5. **全局汇算**：执行 `references/portfolio-overview.md`，计算组合整体收益、基准超额，排查底层同质化风险，并按该文件第 3 节推演极端情景压力测试（压力测试规则以该文件为唯一出处，此处不重复，避免两处版本漂移）。
6. **输出报告**：按 `references/output-format.md` 生成最终报告。

## 数据要求与缺省值

- **最低输入**：标的名称/代码 + 金额或权重。二者缺一时先向用户询问一次，问不到再停止，不要在信息不足时硬算。
- **收益率缺失**：用该标的跟踪指数或同类均值近似，且必须在报告中明确标注"估算"。完全查不到数据的标的，如实说明"未纳入收益计算"。禁止编造精确收益率——这是本技能最重要的诚信底线，宁缺毋假。
- **缺省值**：用户未说明时直接采用以下缺省，并在报告开头列出全部假设，避免反复追问打断用户：
  - 分析区间：今年以来。
  - 基准：境内权益用沪深300，固收类用中证全债，海外权益用对应市场指数（如纳指/标普/恒生）。
- **净值时间序列缺失**（用户只给了区间端点或什么都没给）：只计算区间收益，跳过年化波动率、最大回撤、夏普比率，并在报告中注明"数据不足，未计算"。

## 核心原则

- **聚类透明**：在报告开头必须明确展示"自动分类的结果及依据"，如果存在模糊标的，需向用户说明归类逻辑。
- **客观呈现**：不主观评判用户持仓的好坏，只分析"这些资产拼在一起"产生的化学反应。
- **数据驱动**：收益贡献统一采用**绝对贡献**口径：单主题权重 × 单主题收益率（如 +6.0%）。各主题绝对贡献加总应≈组合总收益率。
- **口径说明**：以当前权重近似区间平均权重。若用户在区间内有已知的大额申赎，需在报告中注明此口径局限——不注明的话，加总校验对不上时会诱使模型为凑数而扭曲数据。

## 收尾自检

报告输出前逐项核对，全部通过再交付：
- [ ] 报告开头展示了**自动聚类**的结果和依据？
- [ ] 各主题的绝对贡献（仓位 × 收益率）加总，≈组合的总收益率？（允许微小计算误差）
- [ ] 是否识别出了"表面上主题分散，但底层资产高度同质化"的风险？
- [ ] 压力测试是否给出了具体的预估回撤区间？
- [ ] 是否包含了"不构成投资建议"的免责声明？
